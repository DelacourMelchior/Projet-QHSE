### M2-01 [MAJEUR · M] Le pied de la fiche mange l'écran d'un téléphone : 5 rangées (225 px) à 375 x 667, 6 rangées (277 px) à 320 x 568
Preuve : `out/sheet_geom.json` (script `sheet_geom.mjs`). Fiche « Centre d'usinage » ouverte : 375 x 667 : en-tête 84 + pied **225 px (5 rangées, 34 % de l'écran)** = zone défilante de 305 px dont 49 px de barre d'onglets collante ; 320 x 568 : pied **277 px (6 rangées, 49 % de l'écran)**, zone défilante **162 px**, la barre d'onglets est déjà à moitié sous le pied au chargement (onglets à y 261-310, pied qui commence à 291) ; 470 x 800 : 4 rangées (173 px) ; paysage 812 x 375 : pied 121 px (3 rangées), zone défilante 161 px dont 49 px d'onglets, la barre d'onglets est coupée par le pied (captures `graves/sheet-routine.320.png`, `sheet-routine.375.png`, `sheet-routine.land.png`). Code : `EqSheet.tsx:142-154` (jusqu'à 7 boutons et un texte dans le pied : Retirer du service, Supprimer, Dupliquer, Affiche, Feuille PDF, Routine plein écran, état d'enregistrement, Fermer), `common.tsx:57` (`flex-wrap`, pas de repli).
Cas aggravant prouvé (`graves/e-sheet-long-issues.375.png`) : équipement dont la fiche est incomplète et au nom long (80 caractères) : en-tête de 6 lignes (le sous-titre répète le groupe), bandeau d'état, bloc « Fiche complète à 78 % » avec jusqu'à 8 pastilles sur 7 lignes (330 px sur l'équipement retiré, `graves/e-sheet-retired.375.png`), onglets, pied : **aucune ligne du contenu de l'onglet visible à l'ouverture**. Avec le clavier virtuel (viewport réduit de 300 px, `out/kbd.json`) : zone défilante de la fiche = **32 px** à 375 et à 320, soit aucun champ visible.
Pourquoi : scénario : une personne ouvre la fiche d'une machine sur son téléphone pour voir l'anomalie ou taper un nom ; elle voit un en-tête, un bandeau et des boutons d'impression, pas le contenu ; sur 320 x 568 la saisie est impossible tant qu'elle ne referme pas le clavier. 3.2 a le même schéma mais un pied de 121 px (375) / 173 px (320) (`out/compare32.json`) : 3.3 est 1,6 à 1,9 fois plus haut.
Correction : un seul bouton « Fermer » dans le pied, les actions (retirer, dupliquer, affiche, PDF, plein écran) dans un menu « Actions » ou dans l'onglet Fiche ; bloc de complétude replié sur une ligne (« Fiche à 78 % · 3 manques ») ; en-tête sur 2 lignes maximum ; pas de bloc de complétude pour un équipement retiré.

### M2-03 [MAJEUR · S] Liste d'équipements sous 640 px : les lignes ne sont pas tronquées (`line-clamp-2 block`), 131 à 478 px chacune
Preuve : `out/clamp.json` (script `clamp.mjs`). 375 x 667, 8 équipements en service : hauteurs de ligne **478, 312, 263, 313, 214, 165, 164, 131 px = 2 040 px** ; 320 x 640 : 724, 493, 378, 444, 344, 214, 229, 180 = **3 006 px** ; 100 équipements chargés (24 lignes affichées) : **8 232 px**. Style calculé du sous-texte : `display: block`, `-webkit-line-clamp: 2`, `overflow: hidden`, 581 caractères. Cause : `EqCards.tsx:104-105` `className="line-clamp-2 block …"` : dans le fichier construit, `.line-clamp-2{overflow:hidden;display:-webkit-box;…}` est suivi de `.block{display:block}` (positions 1636986 et 1637085 de `livrable/pilotage.html`) : `block` annule le `-webkit-box`, donc aucune troncature ; même motif `EqChecksView.tsx:48`. Captures : `graves/full_main-top.375.s2.png`, `full_main-top.375.s3.png` (la ligne « Cabine de peinture » fait 25 lignes de texte, le nom de l'équipement y revient trois fois).
Pourquoi : c'est la vue par défaut d'un téléphone (`Maintenance.tsx:45`) ; l'orchestrateur avait vu que les lignes joignent les textes de tâche, mais ils ne sont pas bornés : une ligne affiche toutes les tâches de l'équipement (« Réparer… · Faire la routine de… · Lever l'observation… »). La liste « compacte sous 640 px » du besoin (G2) est le contraire de compacte. Les ≥ 640 px (`sm:truncate`) sont corrects.
Correction : supprimer `block` (un `span` devient `div` ou `flex`), ou ne montrer que la première tâche + « +N autres » ; ne pas répéter le nom de l'équipement dans le texte de tâche affiché sur sa propre ligne.

### M2-05 [MAJEUR · S] « Équipement à l'arrêt » est collé sous « Suivant » (8 px), écrit sans confirmation, et un double tap crée une panne de 0 h
